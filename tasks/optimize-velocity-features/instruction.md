Our fraud-scoring batch job at `/app/engine.py` computes velocity features for every transaction, and it has blown past its nightly SLA — it's quadratic, so on a full day of traffic it runs for hours. Make it fast: rewrite `/app/engine.py` so that `python3 /app/engine.py` reads `/app/data/transactions.jsonl`, writes `/app/output.json` with the exact same results, and finishes in well under a minute on a full day's data. Use only the Python standard library.

Each line of the input is one transaction — `{"account": <string>, "ts": <integer seconds>, "amount": <integer ≥ 0>}`. For a given transaction, consider the transactions on the same account whose timestamp falls in the trailing one-hour window — those with a `ts` between this transaction's `ts - 3600` and its `ts`, inclusive. Membership is decided purely by the timestamp value, not by position in the file: a transaction with the same `ts` is inside the window, whether it appears earlier or later in the file, and the input is not assumed to be sorted. From that window compute three numbers — `count`, the number of *other* transactions in it (this transaction itself is never counted); `sum_amount`, the total of those other transactions' amounts; and `max_repeat`, the largest number of transactions in the window that share a single `amount` value, counting this transaction itself.

Write `/app/output.json` as a JSON array with one object per input transaction, in the same order, each shaped `{"count": ..., "sum_amount": ..., "max_repeat": ...}`. The numbers must match what the current job already produces — only the running time should change.

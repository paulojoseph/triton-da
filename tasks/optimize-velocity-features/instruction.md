Our fraud-scoring batch job at `/app/engine.py` computes velocity features for every transaction, and it has blown past its nightly SLA — it's quadratic, so on a full day of traffic it runs for hours. Make it fast: rewrite `/app/engine.py` so that `python3 /app/engine.py` reads `/app/data/transactions.jsonl`, writes `/app/output.json` with the exact same results, and finishes in well under a minute on a full day's data. Use only the Python standard library.

Each line of the input is one transaction — `{"account": <string>, "ts": <integer seconds>, "amount": <integer ≥ 0>}` — and the file is in the order the transactions occurred. For a given transaction, the features look only at the *other* transactions on the same account whose timestamp falls in the trailing one-hour window: that is, those with a `ts` between this transaction's `ts - 3600` and its `ts`, inclusive. A transaction at the exact same `ts` counts; the transaction itself never counts. Over that set, compute three numbers — `count` (how many there are), `sum_amount` (the total of their amounts), and `count_ge` (how many had an amount greater than or equal to this transaction's amount).

Write `/app/output.json` as a JSON array with one object per input transaction, in the same order, each shaped `{"count": ..., "sum_amount": ..., "count_ge": ...}`. The numbers must match what the current job already produces — only the running time should change.

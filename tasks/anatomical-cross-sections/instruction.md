A surgical-planning tool needs exact cross-sectional measurements of anatomical structures. Under `/app/data/` you'll find `mesh.obj` — a closed, watertight, outward-oriented triangle mesh of an organ whose vertex coordinates are integers — and `planes.json`, a JSON array of cutting planes, each written as four integers `[a, b, c, d]` for the plane `a*x + b*y + c*z = d`.

For every plane, measure the cross-section of the solid bounded by the mesh — the planar region the plane carves through the solid — together with the volume of solid lying on each side. Write your program to `/app/slice.py` so that running `python3 /app/slice.py` reads those two files and writes `/app/result.json`; we run the same tool on other organ meshes, so it has to work from the files rather than from hard-coded answers. The mesh is not convex and need not be simply connected: a single plane can produce several disjoint cross-section regions, and a region may be an annulus (a ring with a hole). A plane may also pass exactly through vertices or edges of the mesh; these cases are part of the data and must be handled exactly, not by nudging the plane off them.

Write `/app/result.json` as a JSON array with one object per plane, in the same order as `planes.json`. Each object has the keys: `loops` — the integer number of closed contour loops that bound the cross-section region (a plain disk is 1, two disjoint disks are 2, an annulus is 2); `area` — the total area of the cross-section region (the hole of an annulus is excluded); `perimeter` — the combined length of all its boundary loops; `volume_positive` and `volume_negative` — the volumes of solid on the `a*x+b*y+c*z > d` and `< d` sides respectively. `loops` is an integer; the other four are numbers in the mesh's coordinate units (areas in units squared, volumes in units cubed). A plane that only grazes the solid at a vertex or edge, without enclosing any region, has `loops` 0 and `area` 0.

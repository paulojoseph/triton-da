A machinist describes a solid part as a stack of planar cuts: the finished part is whatever material satisfies every cut at once. Each cut is a closed half-space `a*x + b*y + c*z <= d` with integer `a, b, c, d`, and together they carve out one bounded convex solid. Some of the listed cuts are slack and never actually touch the finished part, and the corners where cuts meet usually land on fractional coordinates, so the geometry has to be worked out exactly rather than with floating point.

Under `/app/data/` you'll find `halfspaces.json`, a JSON array of `[a, b, c, d]` cuts, and `queries.json`, a JSON array of integer probe points `[x, y, z]`. The half-spaces always define a bounded solid with non-zero volume. Write your program to `/app/polytope.py` so that `python3 /app/polytope.py` reads both files and writes `/app/result.json`. The order of the cuts in the file carries no meaning; your answer must come out the same if they are reordered.

Report the finished solid's geometry. A face is a flat patch of its surface with positive area, lying on one cut's plane; a cut whose plane meets the solid only along an edge, only at a single corner, or not at all is not a face. An edge is a straight segment where two faces meet, and a vertex is a corner where three or more faces meet. For each probe point, classify it as `outside` if it breaks any cut; otherwise as `vertex` if it sits exactly on a corner, `edge` if it lies on an edge but is not a corner, `face` if it lies on a face but not on an edge, and `inside` if it is strictly within the solid.

Write `/app/result.json` as one JSON object with exactly these keys: `num_vertices`, `num_edges`, and `num_faces` (integers); `volume` (a number, the solid's volume); `face_sizes` (a JSON array of integers, the number of vertices on each face, sorted in ascending order); and `classification` (a JSON array of strings, one per probe point in `queries.json` order, each one of `inside`, `outside`, `vertex`, `edge`, `face`).
